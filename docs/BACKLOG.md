# BACKLOG — 市集銷售記錄 PWA

延後/被否決但日後可能重啟的項目。格式:項目 — 為何延後 — 重啟觸發條件。

## 延後功能

- **雲端同步 / 多裝置 / 自動備份** — 對單人單機是過度設計,且需後端+登入+同步衝突處理。重啟觸發:換新手機需無痛搬移、或多人/多裝置同時記帳。緩解現況:資料可匯出 CSV。
- **跨日區間加總報表**(例:本月營收) — 目前對帳一次看一天。重啟觸發:使用者需要週/月結算。
- **逐品項(line-item)CSV 匯出 / 商品銷售排行** — 目前 CSV 為一筆銷售一列。重啟觸發:想分析哪些商品好賣。
- **更多付款方式 / 自訂付款方式** — 目前固定現金、轉帳。重啟觸發:開始收行動支付/刷卡。
- **折扣 / 抹零** — 目前照定價加總。重啟觸發:現場常需湊整數或給折扣且影響對帳準確。
- **庫存追蹤 / 扣庫存 / 低量提醒** — 目前只記流水帳。重啟觸發:需要知道剩多少、避免超賣。

## 已實作但刻意縮限的範圍

- **對帳編輯一筆銷售時「新增品項」** — 目前編輯只支援調整既有品項數量(減到 0 即移除)與改付款方式;要新增一個原本不在這筆的商品,請刪除該筆後重記。理由:符合「修正記錯」的核心需求且避免在對帳頁重建完整銷售編輯器。重啟觸發:使用者常需在事後往既有銷售補加品項。

## 技術債 / 重新評估點

- **UI 框架** — 現採零相依、免建置原生 PWA。若功能顯著膨脹、原生 DOM 操作難維護,重新評估輕量框架(Svelte/Vue + Vite + vite-plugin-pwa)。
- **自動化 E2E(Playwright)** — 目前 UI 熱路徑以手動冒煙為主。重啟觸發:回歸測試成本升高。
